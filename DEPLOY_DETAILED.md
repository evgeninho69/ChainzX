## 2. Подготовка к деплою

### Шаг 2.1: Получение данных для подключения

Вам понадобятся следующие данные:

#### A. Данные для SSH/FTP доступа к Beget:
- **SSH хост:** `username@your-domain.beget.tech` (или IP адрес)
- **SSH пароль** или путь к SSH ключу
- **Путь к домашней директории:** обычно `/home/u/username/` (узнайте в панели Beget)

#### B. Данные Telegram бота:
- **BOT_TOKEN:** получите у [@BotFather](https://t.me/BotFather) в Telegram
  1. Откройте Telegram
  2. Найдите @BotFather
  3. Отправьте `/newbot` или `/token`
  4. Следуйте инструкциям
  5. Скопируйте токен (формат: `123456789:ABCdefGHIjklMNOpqrsTUVwxyz`)

#### C. Данные для админ-панели:
- **ADMIN_PASSWORD:** придумайте надежный пароль (минимум 12 символов, буквы + цифры + символы)

### Шаг 2.2: Подготовка переменных окружения

Создайте файл `.env` на основе `.env.example`:

```bash
# Скопируйте пример
cp .env.example .env

# Откройте файл для редактирования
nano .env  # или используйте любой текстовый редактор
```

**Заполните файл `.env` (пока без DATABASE_URL, его добавим после создания БД):**

```env
# Telegram Bot Token (обязательно!)
BOT_TOKEN=ваш_токен_от_BotFather

# Database URL (заполним после создания БД)
DATABASE_URL=postgresql://username:password@localhost:5432/chainz

# Admin Panel Password (обязательно!)
ADMIN_PASSWORD=ваш_надежный_пароль_минимум_12_символов

# Node Environment
NODE_ENV=production

# Port для приложения
PORT=3000
```

**⚠️ ВАЖНО:** Не коммитьте файл `.env` в Git! Он должен быть в `.gitignore`.

## 3. Настройка базы данных PostgreSQL

### Шаг 3.1: Создание базы данных в панели Beget

1. **Войдите в панель управления Beget:**
   - Откройте https://cp.beget.com
   - Введите логин и пароль

2. **Перейдите в раздел "Базы данных":**
   - В меню найдите "Базы данных" или "PostgreSQL"
   - Нажмите "Создать базу данных"

3. **Заполните форму создания БД:**
   - **Имя базы данных:** `chainz` (или другое имя)
   - **Пользователь:** создайте нового пользователя или используйте существующего
   - **Пароль:** придумайте надежный пароль (запишите его!)
   - **Хост:** обычно `localhost` или IP адрес (будет указан)
   - **Порт:** обычно `5432`

4. **Сохраните данные подключения:**
   Запишите где-нибудь:
   ```
   Host: localhost (или IP)
   Port: 5432
   Database: chainz
   Username: ваш_username
   Password: ваш_пароль
   ```

### Шаг 3.2: Формирование DATABASE_URL

Сформируйте строку подключения в формате:
```
postgresql://username:password@host:port/database
```

**Пример:**
```
postgresql://chainz_user:MySecurePass123@localhost:5432/chainz
```

**Обновите `.env` файл:**
```env
DATABASE_URL=postgresql://chainz_user:MySecurePass123@localhost:5432/chainz
```

## 5. Настройка на сервере

### Шаг 5.1: Подключение к серверу

```bash
ssh username@your-domain.beget.tech
cd ~/chainz  # или путь, куда вы загрузили проект
```

### Шаг 5.2: Проверка Node.js

```bash
# Проверьте версию Node.js
node --version

# Если Node.js не установлен или версия старая:
# В панели Beget настройте версию Node.js (18.x или 20.x)
```

### Шаг 5.3: Установка зависимостей

```bash
# Установите только production зависимости
npm install --production

# Это установит все зависимости из package.json
# Процесс может занять 1-3 минуты
```

**Если возникли ошибки:**
- Проверьте версию Node.js (должна быть 18+)
- Проверьте доступное место на диске: `df -h`
- Проверьте права доступа: `ls -la`

### Шаг 5.4: Установка TypeScript для сборки

```bash
# Установите TypeScript глобально или локально для сборки
npm install typescript --save-dev

# Или установите все зависимости (включая dev)
npm install
```

### Шаг 5.5: Сборка проекта

```bash
# Скомпилируйте TypeScript
npm run build

# Проверьте результат
ls -la dist/
# Должны быть папки: bot, database, services, admin и т.д.
```

**Если сборка не удалась:**
- Проверьте ошибки в выводе
- Убедитесь, что TypeScript установлен: `npm list typescript`
- Проверьте `tsconfig.json`

### Шаг 5.6: Создание файла .env

```bash
# Скопируйте пример
cp .env.example .env

# Откройте для редактирования
nano .env
```

**Заполните файл `.env` на сервере:**

```env
BOT_TOKEN=ваш_токен_от_BotFather
DATABASE_URL=postgresql://username:password@localhost:5432/chainz
ADMIN_PASSWORD=ваш_надежный_пароль
NODE_ENV=production
PORT=3000
```

**Сохраните файл:**
- В nano: `Ctrl+O` (сохранить), `Enter` (подтвердить), `Ctrl+X` (выйти)
- В vi: `:wq` (сохранить и выйти)

### Шаг 5.7: Запуск миграций базы данных

```bash
# Запустите миграции для создания таблиц
npm run migrate:prod
```

**Что делают миграции:**
- Создают таблицу `users`
- Создают таблицу `referrals`
- Создают таблицу `guilds` и `guild_members`
- Создают таблицу `characters` и `user_characters`
- Вставляют начальные данные (персонажей)

**Проверка результата:**
```bash
# Подключитесь к базе данных (если psql доступен)
psql $DATABASE_URL -c "\dt"
# Должны отобразиться все таблицы
```

**Если миграции не запускаются:**
- Проверьте `DATABASE_URL` в `.env`
- Убедитесь, что база данных создана
- Проверьте права пользователя БД
- Проверьте, что `psql` доступен: `which psql`

## 6. Настройка Node.js приложения в панели Beget

### Шаг 6.1: Вход в панель управления

1. Откройте https://cp.beget.com
2. Войдите с вашими учетными данными

### Шаг 6.2: Переход в раздел Node.js

1. В главном меню найдите **"Node.js приложения"** или **"Node.js"**
2. Нажмите на него

### Шаг 6.3: Создание нового приложения

Нажмите кнопку **"Создать приложение"** или **"Добавить"**

**Заполните форму:**

1. **Название приложения:** `chainz` (или любое другое)

2. **Путь к приложению:**
   ```
   /home/u/username/chainz
   ```
   Замените `username` на ваш username на Beget.

3. **Файл запуска:**
   ```
   server.js
   ```

4. **Порт:**
   ```

   ```
   Или другой свободный порт (проверьте в панели, какие порты доступны)

   Выберите `18.x` или `20.x` (рекомендуется последняя стабильная)

В настройках приложения найдите раздел **"Переменные окружения"** или **"Environment Variables"**

**Добавьте следующие переменные:**

| Переменная | Значение | Пример |
|------------|----------|--------|
| `BOT_TOKEN` | Токен от BotFather | `123456789:ABCdef...` |
| `DATABASE_URL` | Строка подключения к БД | `postgresql://user:pass@localhost:5432/chainz` |
| `ADMIN_PASSWORD` | Пароль для админ-панели | `MySecurePass123!` |
| `NODE_ENV` | Режим работы | `production` |
| `PORT` | Порт приложения | `3000` |

**Как добавить:**
1. Нажмите "Добавить переменную"
2. Введите имя переменной (например, `BOT_TOKEN`)
3. Введите значение
4. Сохраните
5. Повторите для всех переменных

**⚠️ ВАЖНО:** 
- Не используйте пробелы в значениях
- Используйте кавычки только если значение содержит специальные символы
- Проверьте правильность `DATABASE_URL` (особенно пароль с спецсимволами)

1. **Сохраните все настройки**
2. **Нажмите кнопку "Запустить"** или **"Start"**
3. **Подождите 10-30 секунд** для запуска

## 7. Проверка работы

### Шаг 7.1: Проверка бота в Telegram

1. **Откройте Telegram**
2. **Найдите вашего бота** по username (указан при создании у BotFather)
3. **Отправьте команду `/start`**
4. **Бот должен ответить** приветственным сообщением

**Если бот не отвечает:**
- Проверьте логи в панели Beget
- Убедитесь, что `BOT_TOKEN` правильный
- Проверьте, что приложение запущено

### Шаг 7.2: Проверка админ-панели

1. **Откройте в браузере:**
   ```
   https://your-domain.com/admin
   ```
   Замените `your-domain.com` на ваш домен

2. **Должно появиться окно авторизации** (Basic Auth)
   - **Username:** можно оставить пустым или любое значение
   - **Password:** пароль из `ADMIN_PASSWORD`

3. **После входа должна открыться админ-панель** со статистикой

**Если админ-панель не открывается:**
- Проверьте, что домен настроен в Beget
- Проверьте настройки проксирования (`.htaccess`)
- Проверьте логи приложения

### Шаг 7.3: Проверка API

1. **Откройте в браузере или используйте curl:**
   ```bash
   curl https://your-domain.com/api/stats
   ```

2. **Должен запросить авторизацию** (Basic Auth)

3. **После авторизации должен вернуть JSON** со статистикой:
   ```json
   {
     "total_users": 0,
     "new_users_24h": 0,
     "total_links": 0,
     ...
   }
   ```

### Шаг 7.4: Проверка health endpoint

```bash
curl https://your-domain.com/health
```

**Должен вернуть:**
```json
{
  "status": "ok",
  "timestamp": "2025-01-XX..."
}
```

## 8. Решение проблем

### Проблема: Бот не отвечает

**Возможные причины и решения:**

1. **Неправильный BOT_TOKEN**
   ```bash
   # Проверьте токен в .env на сервере
   ssh username@server
   cat ~/chainz/.env | grep BOT_TOKEN
   ```
   - Убедитесь, что токен правильный (без пробелов, без лишних символов)
   - Получите новый токен у @BotFather если нужно

2. **Приложение не запущено**
   - Зайдите в панель Beget
   - Проверьте статус приложения (должно быть "Запущено")
   - Перезапустите приложение

3. **Ошибки в логах**
   - Откройте логи в панели Beget
   - Найдите ошибки (обычно красным цветом)
   - Скопируйте ошибку и поищите решение

### Проблема: Ошибка подключения к базе данных

**Симптомы:**
- В логах: `error: connection refused` или `permission denied`
- Приложение не запускается

**Решения:**

1. **Проверьте DATABASE_URL:**
   ```bash
   # На сервере
   echo $DATABASE_URL
   # Или
   cat ~/chainz/.env | grep DATABASE_URL
   ```

2. **Проверьте формат DATABASE_URL:**
   ```
   Правильный формат: postgresql://username:password@host:port/database
   ```
   - Убедитесь, что нет пробелов
   - Если пароль содержит спецсимволы, закодируйте их (например, `@` → `%40`)

3. **Проверьте доступность базы данных:**
   ```bash
   # Попробуйте подключиться напрямую
   psql $DATABASE_URL -c "SELECT NOW();"
   ```

4. **Проверьте права пользователя БД:**
   - В панели Beget проверьте настройки пользователя БД
   - Убедитесь, что пользователь имеет права на базу данных

### Проблема: "Cannot find module"

**Симптомы:**
- В логах: `Error: Cannot find module '...'`
- Приложение не запускается

**Решения:**

1. **Переустановите зависимости:**
   ```bash
   ssh username@server
   cd ~/chainz
   rm -rf node_modules
   npm install --production
   ```

2. **Пересоберите проект:**
   ```bash
   npm run build
   ```

3. **Проверьте пути в server.js:**
   - Убедитесь, что пути к модулям правильные
   - Проверьте, что папка `dist/` существует и содержит файлы

### Проблема: Порт занят

**Симптомы:**
- В логах: `Error: listen EADDRINUSE: address already in use :::3000`
- Приложение не запускается

**Решения:**

1. **Используйте другой порт:**
   - В панели Beget измените порт на другой (например, 3001, 3002)
   - Обновите `PORT` в переменных окружения
   - Перезапустите приложение

2. **Или остановите процесс, занимающий порт:**
   ```bash
   # Найдите процесс на порту 3000
   lsof -i :3000
   # Или
   netstat -tulpn | grep 3000
   
   # Остановите процесс (замените PID на реальный)
   kill -9 PID
   ```

### Проблема: Миграции не запускаются

**Симптомы:**
- Ошибки при выполнении `npm run migrate:prod`
- Таблицы не создаются

**Решения:**

1. **Проверьте доступность psql:**
   ```bash
   which psql
   # Если команда не найдена, psql не установлен
   ```

2. **Запустите миграции вручную:**
   ```bash
   # Подключитесь к БД
   psql $DATABASE_URL
   
   # Выполните SQL из файлов миграций вручную
   \i dist/database/migrations/001_init.sql
   \i dist/database/migrations/002_guilds.sql
   \i dist/database/migrations/003_characters.sql
   ```

3. **Проверьте права пользователя:**
   - Убедитесь, что пользователь БД имеет права на создание таблиц

### Проблема: Админ-панель не открывается

**Симптомы:**
- Страница не загружается
- Ошибка 404 или 500

**Решения:**

1. **Проверьте настройки домена:**
   - В панели Beget убедитесь, что домен настроен
   - Проверьте настройки DNS

2. **Проверьте .htaccess:**
   - Убедитесь, что файл `.htaccess` загружен на сервер
   - Проверьте настройки проксирования

3. **Проверьте путь к статическим файлам:**
   - Убедитесь, что папка `dist/admin/public` существует
   - Проверьте файл `dist/admin/public/index.html`
